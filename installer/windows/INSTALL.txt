WorkBuddy Gateway - Windows installation
=======================================

This folder is the unpacked installer payload. You normally do not need to read
this: the setup program already installed everything.

If you are installing from this folder manually (for example on a machine where
running a downloaded .exe is blocked), open a command prompt here and run:

    workbuddy-gateway.exe install

That is the same command the setup program runs. Useful switches:

    -dir <path>       install somewhere other than the default
    -autostart        also start the gateway hidden at logon
    -no-register      lay down files only; write no shortcuts, no uninstall
                      entry, no autostart (a "green"/portable install)

Run it with -h to see the rest.

What gets installed
-------------------
    %LOCALAPPDATA%\WorkBuddy Gateway
        workbuddy-gateway-desktop.exe   the window + tray shell (desktop build)
        bin\workbuddy-gateway.exe       the gateway (admin panel is embedded)
        bin\wb-local-agent.exe          optional: powers the "local client" page
        run.cmd                         launcher used by the shortcuts
        launch-hidden.vbs               hidden-start helper for logon autostart
        uninstall.cmd                   uninstaller

    %LOCALAPPDATA%\wb-gateway
        credentials (workbuddy*.json), config.json, model cache, usage stats

Everything is per-user: no administrator rights are needed and nothing is written
outside your own profile.

Upgrading
---------
Run the newer setup program. It installs over the same directory: running
processes are stopped, the old directory is replaced atomically, and your data
directory is never touched. You do not need to uninstall first -- and unlike the
old NSIS-based installers, choosing to uninstall first does not fail.

Uninstalling
------------
Settings > Apps > "WorkBuddy Gateway" > Uninstall, or run uninstall.cmd from the
install folder. Your data directory is kept unless you explicitly pass -drop-data
(it contains credentials).

Because Windows will not let a running program delete the folder it lives in, the
uninstall finishes in a copy of itself placed in %TEMP%; the window may close
before the folder is gone.

Two things worth knowing
-----------------------
1. At startup the gateway pulls the model catalog once before it starts listening,
   so the first /healthz answer takes about 30 seconds. This is by design, not a
   hang.

2. The setup program is not code-signed. Windows SmartScreen may therefore warn you
   on first run. This is the same situation as most small open-source tools;
   choose "More info" > "Run anyway" only if you obtained the file from a source
   you trust.
